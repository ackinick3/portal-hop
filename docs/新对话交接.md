## 2. 已有机制与已确认约束

- A/D移动、Space跳跃、左右鼠标放红/蓝门，R重试，Esc暂停，F11全屏。
- 普通地面跑速210、加速度1400、松键减速2300；用户认可小幅地面滑行（约8.71px）。跳跃-330、重力900；空中按键380、松键仅横向90减速。不要为新关暗改这些数值。
- 门在有效浅色表面自由放置，72px真实碰撞开口，射线不穿墙；边缘命中整扇门内贴。人物22×30。门只继承速度大小，`v_out=length(v_in)*n_out`，方向完全沿出口法线，不保留切向速度，不加关卡专属奖励。
- 枪随鼠标转向，有射击轨迹；绿色墙/顶/地面按等角反射枪线，使枪能打到直射被挡的浅色面。绿色目前不反射激光。
- 蓝色材质接触自动反弹，保留碰撞前切向速度；红色材质在地面助跑加速，离开后保留速度。单材质关仍可用传送门，这是用户明确确认的。
- 现有**琥珀色激光是非致命解谜光束**，可经激活的双传送门改变路径；真实照射接收器后信号锁存到R/重启，能开门或启动平台。
- 移动平台有真实碰撞及承载、扫掠避碰，底部齿轮旋转，背景双凹槽对齐齿轮行进轨迹。平台本身目前不能放传送门。
- 巡逻守卫可从上方踩踏，侧碰致死；第三关普通跳跃踩怪是合法路线。
- B“圆润玩具科技”旗帜/终点门、动作反馈、合成音效继续沿用。

## 3. 最新用户提出的下一阶段需求（尚未实现）

### 可拿取的方块

- 是有实体碰撞、有一定惯性的方块。
- 用户原话：“按住e可以拿起，再按一次可以放下”。使用E进行拿取/放下；尚未落实具体输入触发与持有细节。
- 放置后可以压住按钮，形成关卡机关。
- 方块可以阻挡激光传播，需要真实光路遮挡，不能只在视觉上盖住光线。

### 压力按钮

- 至少支持被方块压住并触发机关。
- 与哪些门/平台相连由用户接下来的关卡设计决定。

### 红色致死激光

- 新增红色激光，角色碰到会死亡。
- 方块能挡住激光，便于保护玩家或解谜。
- 当前琥珀色光束已有非致命接收器功能；新需求中红色与琥珀色的最终关系需要结合用户设计落实，**不要把现有光束已变致命写成事实**。

以上三项现在都只是需求，没有相应源码/关卡/测试或新EXE实现。用户明确这次先总结对话，之后新开对话设计关卡；本轮不提前实现。

## 4. 后续设计需明确的细节

新对话在用户给出地图/机制设计时再确定，不必现在逐项追问：

- E是按一下切换拿取/放下，还是需要持续按住；拿取距离、持有位置、放下后速度如何继承。不要未经确认增加投掷/重力枪等额外功能。
- 方块质量/阻尼、能否推、能否穿传送门/受材质或平台影响；目前没有用户确认的具体数值与交互规则。
- 按钮是否仅在受压时工作、方块离开后是否复位、玩家能否直接踩；不要直接照搬现有接收器的锁存逻辑。

## 5. 代码与存档入口

- `levels/maps.gd`：`LEVEL_COUNT=23`，`ROOM_IDS`保存稳定原ID，`get_level()`只接受当前索引0..22，`index_for_id()`把稳定ID换成当前索引。关卡显示编号与旧ID不要混用。
- `levels/campaign.gd`、`coating_rooms.gd`、`laser_rooms.gd`、`advanced_rooms.gd`保存保留关卡；章节内部索引仍按稳定原ID减一，入口统一经maps。
- `actors/player.gd`：角色移动、瞄准、碰撞/死亡、涂层反弹与加速；E交互尚未添加。
- `portals/system.gd`：真实门洞、候选落点、枪反射、激光路径、动态occluders。以后方块遮光应与此系统及真实碰撞一致。
- `world/mechanisms.gd`：发射器、接收器、门锁/平台与信号复位；`world/moving_platform.gd`负责平台实体/承载/齿轮轨道。
- `scenes/main.gd`：关卡生命周期、菜单、3页选关、进度、R/暂停/结算及瞄准反馈。
- 存档在`%APPDATA%/Godot/app_userdata/Portal Hop/progress.cfg`。新存档`order_version=2`使用新编号；旧50关存档迁移到首个保留ID≥旧最高解锁ID，新版不重复迁移。测试`persistence_enabled=false`，不写真实存档。
- 以后新加关不能只改LEVEL_COUNT；需同步稳定ID路由、选关/最终页、进度兼容与真实通关测试。不要复用已删旧ID。
