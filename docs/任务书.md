# 一、游戏基本信息

**游戏名称：Portal Hop（暂定）**

类型：2D 横版动作解谜平台游戏。

目标平台：Windows PC。

开发引擎：Godot 4 稳定版。

开发语言：GDScript。

玩法参考：经典横版平台闯关游戏和《Portal》系列的空间传送机制。

游戏风格：几何极简风格（Minimalist Geometric Style）。

模式：单人、离线、独立关卡闯关。

核心设计理念：

玩家能够像传统平台游戏一样奔跑、跳跃、躲避危险、踩踏敌人，同时使用鼠标在符合条件的地形表面创建红蓝传送门，在两扇门之间双向传送。

传送不仅改变玩家的位置，还要保留并转换运动速度，使玩家能够利用重力完成高速弹射和特殊跳跃。

本游戏要求动作操作与传送门解谜同样重要。

**第一期开发目标：完成三关可玩的 MVP，包含完整的开始、挑战、死亡、复活、通关和关卡切换流程。**

未来计划扩展为五关，但暂不开发第四、第五关。

所有游戏角色、场景和 UI 均应采用原创或授权允许的资源，不使用马里奥或 Portal 的受版权保护角色、美术和音乐。

# 五、红蓝传送门系统

这是本项目最重要的系统。

## 5.1 基本规则

1. 玩家鼠标左键发射红门。
2. 鼠标右键发射蓝门。
3. 场景最多存在一扇红门和一扇蓝门。
4. 两扇门都存在时才允许传送。
5. 玩家进入任何一扇门，都可以从另一扇门离开。
6. 同种颜色重新发射时，替换原有的同色门。
7. 放置失败时，原有门不发生变化。
8. 玩家死亡后清除全部传送门。
9. 切换关卡后清除全部传送门。

## 5.2 自由放置规则

玩家可以在符合条件的水平地板、竖直墙壁和天花板上自由选择放门位置。

并不是固定插槽传送门。

第一期只支持水平和竖直表面，不支持斜面、曲面和移动平台上的门。

初始门开口长度为 72 px。

只有在以下条件同时满足时才允许放门：

- 目标位于当前摄像机可见范围。
- 目标位于有效材质的表面。
- 传送枪到目标之间没有实体障碍阻挡。
- 表面拥有足够连续长度。
- 整扇门能够完整放下。
- 不与已有另一扇门重叠。
- 门的入口和出口空间不会与固定实体地形发生非法重叠。

射击射线从角色的传送枪附近发出，沿鼠标瞄准方向检测。

不能穿墙射击。

如果多个相邻碰撞体形成连续的有效表面，放置判定应依据连续表面，而不只是单个碰撞体。

需要提供鼠标准星或有效放置位置的简单预览反馈。

## 5.3 传送门视觉状态

- 尚未放置：不存在。
- 只有一扇门：低亮度，不激活。
- 两扇门存在：稳定发光，传送激活。
- 成功传送：入口与出口短暂增强亮度。
- 无效放置：显示简短的失败反馈。

第一期不做“透过传送门实时看到另一侧场景”的复杂视觉效果。

## 5.4 传送门碰撞

必须实现真正的传送门开口。

当两扇门激活时，玩家可以穿过门所在的承载表面，而不能继续被原本的地板或墙壁阻挡。

门外的其余实体表面必须保持正常碰撞。

只有一扇门存在时，承载表面仍按普通实体处理。

需要保证角色完整经过门的有效开口，不能仅因边缘轻微接触就直接传送。

# 六、传送门的运动速度转换

**核心原则：传送门改变速度方向，不凭空增加或删除速度。**

传送应使用完整的二维速度向量，而不是只处理水平或竖直速度。

设：

- n_in：入口门朝向开放空间的单位法线
- n_out：出口门朝向开放空间的单位法线
- t_in、t_out：由统一方向约定确定的门表面切向单位向量
- v_in：玩家进入门前的速度
- v_out：玩家离开门后的速度

推荐采用以下统一转换规则：

v_out = -dot(v_in, n_in) × n_out + dot(v_in, t_in) × t_out

其中切向基必须对所有朝向采用一致定义，例如在游戏坐标系中令 t = (-n_y, n_x)。

如果实际实现使用矩阵或其他等价方式，也必须满足相同的设计意图。

该规则应保证：

- 地板门向下进入 → 地板门向上离开。
- 地板门向下进入 → 右向墙门向右离开。
- 地板门向下进入 → 左向墙门向左离开。
- 地板门向下进入 → 天花板门向下离开。
- 墙面门可以连接地板和天花板门。
- 斜向进入时保留切向速度分量。
- 理想传送瞬间速度大小不变。
- 出口后继续正常受到重力和移动输入影响。

传送过程中不得为特定关卡偷偷添加速度奖励。

## 6.1 传送极端情况

需要处理：

- 两扇门面对面。
- 门非常靠近。
- 高速连续传送。
- 入口速度很低。
- 斜向进入。
- 角色从天花板门向下离开。
- 出口附近有实体障碍。
- 玩家高速撞到地形或尖刺。
- 玩家试图从门边缘穿入。
- 玩家刚离开出口又与入口区域重叠。

不要简单通过较长的传送冷却时间处理连续传送。

更合理的方式是跟踪角色是否真正脱离出口的有效区域，再允许重新触发。

高速运动应采用可靠的碰撞检测，避免角色穿透薄墙或危险区域。

如果当前引擎或架构对完全自由的地板开口存在技术限制，请先实现一个最小测试场景验证解决方案，再开发正式关卡。不得用只有视觉效果、无法实际穿越的假门替代。

# 七、死亡和检查点

玩家没有生命值系统。

以下情况立即死亡：

- 碰到尖刺。
- 落入致命深坑。
- 与敌人发生危险接触。
- 其他明确标记的致命障碍。

例外：玩家从上方有效踩踏敌人，可击败敌人而不死亡。

死亡后：

1. 播放简短死亡反馈。
2. 回到最近激活的检查点。
3. 清除红蓝传送门。
4. 恢复敌人状态。
5. 恢复该关卡需要重置的机关状态。
6. 保留本次关卡的死亡次数。

每关起点默认是检查点。

第一期每关可以暂时只设置起点检查点，因为独立谜题房间较短。

# 八、敌人系统

第一期只制作一种敌人。

名称：Sentry-01。

造型：暖红色的小型几何机器人。

初始尺寸：40 × 34 px。

巡逻速度：70 px/s。

行为：

- 在指定的平台范围内左右巡逻。
- 碰到墙壁掉头。
- 靠近平台边缘掉头。
- 不追击玩家。
- 不发射子弹。
- 不主动进入传送门。
- 与玩家侧面发生危险接触时玩家立即死亡。
- 被玩家从上方踩中时死亡。
- 玩家踩中后获得一次向上反弹。

有效踩踏要求玩家在接触前处于敌人上方，并具有合理的向下运动趋势。

敌人不进行传送。对敌人而言，传送门承载面仍然视为普通实体地形。

玩家死亡后，敌人复位并重新出现。

第三关才正式引入敌人。

# 九、关卡设计

第一期完成三个独立谜题房间。

每个房间采用 960 × 540 的固定设计视野。

所有关卡共享相同的角色移动、重力、射击和传送规则。

关卡不能通过暗中修改玩家能力或传送速度来降低难度。

关卡设计中的坐标都是初始规格，应在确保游戏可正常通关的前提下调整。

## LEVEL 01 — 两扇门

英文名：The First Crossing。

目的：

- 教会玩家移动和跳跃。
- 教会红蓝传送门放置。
- 让玩家完成第一次空间传送。
- 不出现敌人。

### 地图初始布局

画面尺寸：960 × 540。

主要区域：

| 地形 | 坐标 |
|---|---|
| 左侧地面 | x=0–370，顶部 y=380 |
| 右侧地面 | x=610–960，顶部 y=380 |
| 中间深坑 | x=370–610 |
| 左侧有效放门区域 | x=210–350，y=380 |
| 右侧有效放门区域 | x=650–800，y=380 |
| 玩家出生点 | x≈128，脚底 y=380 |
| 终点 | x≈854–909，底部 y=380 |

深坑宽 240 px，正常跳跃不能直接跨越。

建议在左侧补充一个约 80–100 px 高的小平台，让玩家能够跳到入口门上方并获得一定下落速度。

### 标准通关流程

1. 玩家学习左右移动和跳跃。
2. 观察无法普通跳过的深坑。
3. 在左侧有效地板上放置红门。
4. 在右侧有效地板上放置蓝门。
5. 从小平台跳入红门。
6. 从右侧蓝门向上离开。
7. 在右侧平台安全落地。
8. 前往终点通关。

### 重要技术要求

这里两个门都朝上。

玩家从左侧地板向下进入时，应从右侧地板向上离开。

必须确保角色能够获得足够的出门速度，并且可以通过有限空中控制落到安全地板，而不是不断重新落入蓝门。

如果目前的初始布局无法稳定实现，请保留核心教学目标，调整小平台高度、门区域和右侧落脚空间。

需要实际运行验证。

## LEVEL 02 — 重力弹弓

英文名：Gravity Slingshot。

目的：

- 教会玩家利用下落积累速度。
- 学会地板门到墙门的速度转换。
- 完成一次高速水平飞跃。

### 地图初始布局

画面：960 × 540。

| 地形 | 初始位置 |
|---|---|
| 左侧主地面 | x=0–520，顶部 y=470 |
| 右侧终点平台 | x=700–960，顶部 y=470 |
| 高处起点平台 | x=255–395，顶部 y=145 |
| 红门有效地板 | x=405–520，y=470 |
| 蓝门有效墙面 | x≈180，y≈110–305 |
| 终点 | x≈874–922，底部 y=470 |

墙面门必须朝向右方。

高处平台与下方地板存在约 325 px 的高度差。

### 标准通关流程

1. 玩家出生在高处平台。
2. 观察地板和竖直墙壁的可放门表面。
3. 在墙壁上放置蓝门。
4. 在下方地板上放置红门。
5. 从高台右侧跳下。
6. 利用下落获得速度，进入红门。
7. 从蓝门向右高速飞出。
8. 飞越深渊，在终点平台落地。
9. 抵达终点。

### 物理要求

初步估算：

从约 325 px 高度下落，在重力为 900 px/s² 时，理想入门速度约 765 px/s。

经墙面传送门转换后，这部分速度应成为向右运动速度。

不能使用固定的强制发射速度。

### 需要重点复核

以前的方案将终点平台放在 x=750，理想飞跃余量偏小，因此建议将终点平台左边缘调整到 x≈700。

仍然要求普通跳跃无法直接跨过深渊。

此外，必须检查高速弹射后会不会撞到高处平台底部或其他障碍。

请通过真实游戏物理验证落点，不要只依靠理论估算。

## LEVEL 03 — 机械守卫

英文名：Mechanical Guardian。

目的：

- 引入第一种敌人。
- 学习敌人侧面危险碰撞。
- 学会从上方踩踏敌人。
- 允许玩家用普通跳跃或传送门创造不同路线。

### 地图初始布局

画面：960 × 540。

| 地形 | 初始位置 |
|---|---|
| 主地面 | x=0–670，顶部 y=430 |
| 右侧终点地面 | x=740–960，顶部 y=430 |
| 小深坑 | x=670–740 |
| 起点高台 | x=80–205，顶部 y=350 |
| 左侧红门地板区域 | x=105–265，y=430 |
| 上方天花板有效表面 | x=390–630，底面 y≈197 |
| 机器人巡逻区 | x≈440–580，地面 y=430 |
| 终点 | x≈859–909，底部 y=430 |

### 通关路线 A：普通动作

玩家从高台跳下，观察敌人巡逻节奏。

玩家可以跳过敌人，也可以踩踏敌人将其消灭。

随后越过较小的深坑抵达终点。

### 通关路线 B：传送门空降

1. 玩家在左侧地板创建红门。
2. 在机器人上方的天花板创建蓝门。
3. 从起点高台跳入红门。
4. 从天花板蓝门向下离开。
5. 调整落点，踩踏巡逻机器人。
6. 越过后方深坑并通关。

### 关键要求

- 这关不强制玩家使用传送门。
- 两种路线都应正常可用。
- 敌人始终遵守同一套巡逻规则。
- 玩家从天花板门向下离开时，不添加额外速度。
- 踩踏需要正确的碰撞方向判定。
- 玩家侧面碰到机器人立即死亡。
- 玩家死亡后敌人重新生成。
- 小深坑允许普通跳跃通过。

请特别检查起点高台和上方天花板的位置，确保有效传送门表面能从合理的玩家站位直接射中，不会被其他平台遮挡。

# 十、关卡的统一设计原则

第一关：空间传送。

第二关：动量转换。

第三关：传送门与动作战斗结合。

难度循序渐进。

所有关卡必须遵守：

1. 玩家能够明确识别可放门表面。
2. 不能让关键目标表面被不合理地遮挡。
3. 普通跳跃距离和传送弹射距离由统一物理决定。
4. 关卡必须存在稳定、可以重复完成的通关路线。
5. 不要求像素级完美操作才能完成教学关。
6. 玩家死亡后能够快速重试。
7. 不添加隐藏的关卡专属速度倍率。
8. 允许聪明的非预期解法，只要不破坏基本通关流程。
9. 避免玩家卡死而不能重新开始。
10. 房间布局优先保证核心机制正确，其次才是装饰。

# 十四、重点自动测试要求

请尽可能建立自动化测试或调试测试场景，覆盖：

1. 玩家正常移动与跳跃。
2. 玩家无法穿过普通实体墙。
3. 射击被墙遮挡的目标应失败。
4. 门不能放在无效表面。
5. 门不能放在不足以容纳完整开口的位置。
6. 只有一扇门时不能传送。
7. 红门、蓝门可以互相进入。
8. 重新放置同色门不会留下旧门。
9. 地板到地板速度正确转换。
10. 地板到墙面速度正确转换。
11. 地板到天花板速度正确转换。
12. 墙面到墙面速度正确转换。
13. 斜向进入时合理保留速度大小。
14. 高速弹射不会被跑速上限瞬间截断。
15. 连续传送不出现无限循环。
16. 传送出口不能让玩家卡进地形。
17. 玩家接触尖刺死亡。
18. 玩家从上方踩中敌人，敌人死亡。
19. 玩家撞到敌人侧面死亡。
20. 死亡后恢复检查点。
21. 死亡后红蓝传送门清除。
22. 三关分别能够完成通关。

无法可靠自动测试的项目，请提供人工试玩步骤。

不能仅以项目成功解析或编辑器能够打开作为游戏完成标准。

# 十六、重要限制

不得擅自：

- 改为 3D 游戏。
- 换用其他游戏引擎。
- 改成纯解谜或纯跑酷游戏。
- 移除动量保留机制。
- 把自由放置门变成只能放在固定点。
- 为了简化实现而让传送门不再形成真实开口。
- 让玩家拥有多点生命值。
- 添加多人联机。
- 添加大量敌人种类。
- 添加复杂经济系统、装备或剧情。
- 一次性引入过多未经验证的功能。

如果技术限制使某项关键规则无法直接实现，应先分析替代方案及其对玩法的影响，再决定是否修改。
