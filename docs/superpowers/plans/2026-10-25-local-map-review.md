# 本地地图批注网页

用户已选择本地网页，批准此前提出的翻页、画笔/箭头/文字、撤销、保存/导入/导出功能，并明确先批注、再更新计划图、确认后游戏实装。本次直接执行该范围，不另设网页发布步骤。

## 文件与约束

- `docs/map-review/`：构建脚本、简单网页源文件、Node内置测试、说明。
- `docs/地图批注.html`：生成的单文件本地入口，内嵌现有五关SVG，不依赖网络或服务器。
- `docs/五关布局示意.svg`仍是计划图源；更新它后重建网页，稳定A–E编号保留批注，图版本变化显著提示旧批注可能需复核。
- 自动保存只在当前浏览器；JSON备份用于跨浏览器/交给助手，PNG用于看图。网页不写游戏源码、不自动修改计划图，不声称助手能读取浏览器存储。

## 步骤与验证

1. 先写批注数据测试：关卡隔离、撤销、合法JSON往返、错误导入不覆盖、旧图批注保留并标版本。运行看到缺少实现失败。
2. 实现最小数据层、翻页与canvas工具、文本编辑和列表；加入缩放、自动保存、导入JSON/导出JSON与当前图PNG。生成单文件HTML。运行Node测试、JS语法与构建检查。
3. 浏览器实际检查五关翻页、缩放后落笔/文字、撤销、刷新恢复、导入错误提示和文件导出；检查窄窗口。仅修改测试数据，不留下示例意见冒充用户批注。
4. 更新PROJECT_STATE/README/进度，记录本轮网页验证与游戏未测/未导出。提交Git回滚点并交付本地入口。

## 审阅重点

图像与画笔坐标同比例；导入失败保持原数据；刷新不丢注释；图修订不静默清空旧批注；导出PNG包含底图与批注；文字不作为HTML执行。
