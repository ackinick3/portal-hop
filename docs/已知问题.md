# 已知问题与人工验收

当前为五关试玩版：前三关已有用户认可，第四、五关已通过自动验证，仍等待用户试玩和难度反馈。

## 已知限制

- UI 当前为英文；README 和开发记录为中文。
- 第二关必须先放高处墙门，离开起点平台后才能射到地板。下落时需调整水平速度，有一定操作学习成本。
- 第三关空降前应从高台先射天花板；高台可能遮挡下层部分瞄准角度。这是实体遮挡规则的结果。两条路线均有重复的自动通关记录。
- 第四关先放蓝门，再在走下起点台后放墙红门；起点台会遮挡提前向下射墙的角度。文字教学已按用户要求隐藏，关内有建议圆圈，完整路线见README，实际操作节奏仍待试玩。
- 第五关综合地板→墙弹射与守卫区域落点控制。已验证按A减速踩踏和继续向右绕过两条路线；踩踏不是强制条件，空中调整时机和最后平台的容错仍需人工试玩。关内继续只有建议圈，路线见README。
- 当前为用户选定的B圆润美术方向：旗帜/拱门已经原生绘制，关内不显示顶部文字。原有计时和死亡数仍在结算保留，新外观等待游戏内验收。
- 旧存档只记录解锁到哪一关，无法区分刚解锁和已经通关；旧unlocked=4需要再通关一次第四关解锁第五关，旧unlocked=3同理先通关第三关。不会自动清空或额外解锁存档。
- 按 R 从检查点复位并计一次死亡；暂停菜单的重新开始则清零本关时间和死亡数。
- 已有落地压缩、踩踏拉伸与光环、传送闪光，仍是简易几何动画，最终节奏和力度需要试玩反馈。
- 原音频退出警告已通过复用播放器、停止并释放音频流、退出前等待混音清理处理。第四关回归还复现快速切换后立即退出时60ms等待偶尔不足，现退出时先释放播放器并等待300ms，连续6次立即关闭通过；尚未进行小时级内存测量。
- 门洞沿承载矩形厚度切通，因此未来加入特别薄的双面可放门墙、相交门户或不同高度的复杂连续表面时，应扩充测试。当前五关和四朝向测试通过。
- 已测试间距90px的相向门连续54次穿越、三种窗口比例及全屏切换，瞄准点仍落在同一逻辑表面；对小时级循环、全部刷新率和其他地图仍未做穷尽测试。
- 本次没有自动驱动真实鼠标点击全部菜单，也没有做小时级性能/内存测量。已检查实际GPU渲染截图、鼠标坐标、脚本物理和EXE启动，不把这些等同于完整人工试玩。

## 人工验收步骤

1. 双击 builds/PortalHop.exe（唯一入口，包含最新五关）；确认主菜单、操作说明、音量滑杆正常。
2. 首次关卡选择只应解锁第一关；完成后返回确认后续解锁，重启确认保留。
3. 五关按 README 路线分别完成；检验正常跳跃无法直接跨前两关大坑、第三关小坑能跳过，并重点反馈第四关两种出门方向、第五关弹射踩踏/跳过守卫的落点与容错。
4. 试放单扇门：仍为实体；两门后可穿越。重新放同色门、无效射击、从两颜色反向进入、门边缘擦碰，观察是否符合规则。
5. 坑底尖刺、敌人侧面接触应立即触发死亡；复活应在起点、清门且敌人恢复。
6. Esc暂停期间，角色、敌人和计时停止；继续恢复，返回菜单可重新开始。
7. F11和设置按钮切换全屏；调整窗口尺寸，不应获得额外视野/射程。
8. 重点反馈第二关下落瞄准与刹车难度、第三关踩踏手感、音效音量和教学清晰度。

## 后续开发

第五关已实现；先收集用户试玩反馈，再决定修改或新增内容。继续通过levels/maps.gd定义地图，Maps.LEVEL_COUNT统一驱动数量、解锁和最终页；guard字典可指定同类守卫的出生点与巡逻范围，默认值仍属于第三关。不自动开始第六关。
